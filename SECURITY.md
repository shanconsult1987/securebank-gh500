
# Security Policy

## Supported Versions

| Version | Supported |
|---|---|
| 3.x | Yes |

## Reporting a Vulnerability

Do not disclose vulnerabilities through public GitHub issues.

Report security vulnerabilities through the organization's
approved private security reporting process.

Include:

- Affected component
- Vulnerability description
- Reproduction steps
- Potential impact
- Suggested remediation

## Response Process

1. Security team acknowledges the report.
2. Vulnerability is triaged.
3. Severity and business impact are assessed.
4. Remediation owner is assigned.
5. A fix is implemented and tested.
6. Security team validates closure.

## Security Principles

- Never commit production credentials.
- Use least-privilege permissions.
- Review dependencies before merging.
- Require security checks before production releases.
